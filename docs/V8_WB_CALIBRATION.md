# V8 白平衡校准与 HDMI 参数显示（2026-10）

## 实际测量依据
用户上板白色目标采样（V7 模式 3）：`RAW R:F4 G:6A B:C4 N:100 V:1`，`OUT` 与 `RAW` 相同，原增益 `R:100 G:100 B:100`。
十进制 RGB 均值为 (244,106,196)，G 显著偏低，画面呈紫红色。屏幕采样是 FPGA 图像像素的 16x16 个稀疏点，每帧 256 个样本，**不是传感器内部的 AWB 寄存器**。

## 出厂参考校正（不是万能标定）
使用原设计 Q8 定点增益（0x100=1.0x）设置：

| 通道 | 寄存器 | 实际倍数 | 对本次白色参考的预测 |
|---|---|---|---|
| R | 0x0C0 | 0.7500 | 183 |
| G | 0x1C0 | 1.7500 | 185 |
| B | 0x0F0 | 0.9375 | 183 |

这组参数将三通道拉近，但整体亮度可能比未校正图像低。当前是图像处理端的静态增益，并未修改摄像头曝光、Bayer 解码方向或 AWB 寄存器；不同灯光、白纸位置、白平衡自动状态会改变适合的系数。对于屏幕白色目标，R=244 已接近饱和，建议检查 RGB 是否溢出/削顶，用真实白纸测试时尽量控制曝光。

## HDMI 显示模式和按键
- 开机仍然是模式 3：左右完整场景对比，**不显示三行字符**。
- KEY3 短按可循环模式 0->1->2->3->4->5->6->0；开机默认模式3，按三次 KEY3 短按进入模式6。
- 模式 0：全屏彩色直通、无 HUD。模式 6：全屏彩色直通 + HUD，可用 KEY1/2 调白平衡。其余模式均无 HUD（旧版小型帧数条也隐藏），不改变边缘检测功能。
- 模式 6：KEY3 长按在 `SEL:R/G/B` 之间切换；KEY1 提高，KEY2 降低被选中通道增益，每次 `0x10`（1/16 倍），范围 `0x080` (0.5x) 至 `0x240` (2.25x)。其余模式 KEY1/2 继续调 Sobel 阈值。
- 仅模式 6 显示 `V8` 字样和青色左边标记，便于确认载入的是 V8 固件。
- 文字行 1 `RAW` / `OUT` / `N` / `V`，行 2 `GAIN` / `T` / `MODE` / `KEY` / `SEL`，行 3 `CAM` / `DDR` / `SCREEN` / `ERR` / `FRZ`。数字为十六进制（FPS 计数内部为压缩 BCD；若 HDMI 是 60Hz、每 60 帧统计一次，可近似 FPS）。

## 校准方法
1. 进入模式 6，等待 `N:100 V:1` 稳定，白纸占据画面中央超过一半，并保持 0.5m 左右距离、均匀照明。
2. 读 `RAW` 及 `OUT`，优先调整 `OUT` 三通道差别，建议控制在 ±5~10 内；按键 KEY3 长按选通道。
3. 如果 `OUT` 出现 `FF`，应降低对应增益或减少曝光。避免通过增益补偿严重的曝光或错误 Debayer 格式。
4. 离开模式 6（再次 KEY3 短按进入模式 0），视频正常显示，不再被字符覆盖；新增默认白平衡增益仍然作用于全部视频模式，便于比较校正效果。
5. 拍一张模式 6 的 `RAW`/`OUT`/`GAIN` 与实际白纸画面，我可以据此进一步精细化参数。

## 工程约束/验证
原 Efinity `peri.xml`、`sdc`、IP、DDR、MIPI、HDMI 时钟、摄像头初始化表全部保持不变。新增的是复用已有后 Debayer 增益的初始参数和最终 HDMI HUD 的模式门控。
新工程不包含历史生成的 `.bit/.hex`，必须在全新目录完成 **Efinity 重新综合 → 布局布线 → 生成 bitstream → 烧录**。提供 Python 参考测试和 Verilog testbench，但在本环境无法执行 Efinity 综合及 FPGA 上板验证。
