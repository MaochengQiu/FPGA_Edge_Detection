# E8R：保留 E7 画质的资源优化候选

目标是为后续创新功能释放资源。本版没有新增几何识别，也没有通过减少滤波、放宽连接条件或减小图像分辨率来节省资源。用户已确认 E7 去噪、轮廓和稳定性有所改善；原 E7 发布文件按清单核验保留。

## 烧录与对照

使用 `programming/ti60f225_oob_V10_E8_Resource.bit`，确认屏幕标识 E8R。上电仍为 M3/T50/PRE2，模式和按钮操作保持 E7：PRE0 旁路、PRE1 中值3、PRE2 高斯5、PRE3 高斯3，M7 保留。

实板请使用与 E7 相同的场景、机位、PRE 和阈值。用户最近照片中分别使用过 T32/T73、PRE2，不要把 E8 上电默认 T50 与旧照片的不同阈值直接当成画质变化。比较 M2 的纯黑白边缘、M3 分屏、M7 对照色，以及冻结/恢复和切页；E8 预期画质与 E7 相同。若出现新的断线、像素错位或失锁，应记录并回退 E7，不把资源节省当成上板稳定性已确认。

## 优化一：长延迟 RAM 的物理利用率

E7 的 `img_delay` 使用一个深循环存储器。深度不是物理 RAM 有效组合的整数倍时，综合工具会为部分数据位分配较深且利用率低的 RAM 列。

E8 对超过2049拍的延迟使用2048字分块和精确长度的尾块。每拍只访问当前选中的块，块内仍先读旧数据再写入新数据，记录同一拍的块选择供输出复用。指针回绕、填充计数、复位时的零输出和原延迟拍数保持。短延迟保留 E7 实现。`BANKED_ENABLE=0` 可用于开发对照，不是新增按键功能。

没有缩小 DDR 采集/显示 FIFO，也没有改变跨时钟处理或 DDR 访问节拍。算法窗口、图连接、Sobel/NMS、滤波权重、高低阈值比例、强种子门槛、M2/M7色值不变。

## 优化二：Gamma 固定曲线查表

E7 先从初始 ROM 循环读取1024项曲线，再不断写入可变寄存器数组，RGB三通道从该数组查值。这使工具实现大量存储寄存器和多路选择逻辑。

E8 直接读取同一个曲线文件中的固定只读表。保持8位输入扩展到10位地址的方法、取输出高8位的方法、10位通用路径、DE/HS/VS、空白像素清零及1拍寄存器延迟。最终由工具选择小规模查表逻辑实现，不要求实际占用额外片上 RAM。

明确的初始化差异：E7 的寄存器表首次逐项装载期间，尚未写入项的 RGB 是未定义值；E8 的 ROM 从配置完成起就有确定值。仿真检查新 ROM 每个时钟符合曲线模型，对旧版本所有已经定义的像素要求一致；首次装载后要求完整逐拍一致，且后续复位也一致。没有把旧版 X 当成某个规定的像素值。正常工作阶段的颜色映射未调整。

相机初始化、Bayer相位、RGB增益、gamma选择控制、DDR、E6视频编码器、PLL、串化、驱动强度、引脚和 SDC 保持。Gamma 曲线文件逐字节保留。

## 验证

`verify_e8_units.py` 检查16组延迟位宽/深度组合，覆盖块边界、1字尾块、回绕、填充、复位，以及实际2205/4404/4432/6621拍参数；另检查8位/10位、两种曲线的3组 Gamma 对照。

`verify_e8_core.py` 使用冻结的完整 E7 边缘 RTL，只为双核心仿真重命名模块。逐拍比较新旧 RGB、DE/HS/VS、梯度幅值、边缘位和输入SOF。小图覆盖8个显示页×4种PRE，另用1920像素宽、2200拍行周期验证真实长延迟存储及分屏路径；包含中途复位。E8R HUD 标识单独验证，因为版本文字本来就应不同。

冻结原件位于 `sim/reference/e7_resource/`。结构/接口、8个元数据案例、按键、PRE长按、视频欠载恢复另有实际日志。对原加密IP仅做公开端口检查，没有将接口占位当成IP功能模型。

实际资源、时序、逐项节省和校验和见 `reports/V10_E8_VALIDATION.md`、`e8_release_manifest.json`。新固件改变布局，物理显示稳定性仍需实板确认。目录内 E3～E7 报告及入口都是历史资料，不作为本轮新结果。
