# E6D：保留 M2 纯黑白的输出修复候选

用户的同一 E5 固件对照结果：M7 正常且不黑屏，M2 仍黑屏。两页只改变显示 RGB 码值，处理核心、缓存和视频同步相同。因此本轮针对输出编码路径处理，不调边缘算法或阈值。

这仍不能确定原加密编码器有错误，也不能排除码型相关的串行信号质量、供电或数据路径时序问题。电脑端不能复现板上的显示器失锁，不能将仿真通过称为黑屏已修复。

## 这版改动

当前加密 HDMI 编码实例替换为板卡随附 `03_hdmi_tx_demo/hdmi_tx_demo_v2/rtl/hdmi_src/dvi_tx` 的可检查纯视频编码实现，保留原编码器文件和版权声明供核对。`edge_dvi_encode.v` 与该资料的 `encode.v` 只有模块名不同，包装器明确蓝/绿/红三通道及同步控制映射。原件在 `reference/board_demo_dvi/`。

RGB、DE、HS、VS 经过对齐的三寄存器编码流水，每拍仍处理一个像素。消隐发送 DVI 控制符号，不发送 HDMI 数据岛、音频、AVI 信息帧。使用原 HDMI 接口和原分辨率；本项目原先音频输入已固定禁用。这是传输实现变化，显示器对 DVI 的识别与默认色彩范围仍需实板确认。

M2 边缘为 `FFFFFF`，背景为 `000000`；M7 保留 `E0F0FF/000103` 对照色。M0～M7 操作、T/PRE、NMS、连接、行缓存、灰度、彩色增益、gamma、DDR、摄像头、PLL、复位、引脚、驱动强度、10:1 串化器、输出取反及 SDC 均保留。HUD 仅标识改为 E6D。不能将传输替换描述为边缘增强。

## 烧录与一次验证

烧录 `programming/ti60f225_oob_V10_E6_DVI.bit`，以屏幕 E6D 标识确认实际加载版本。

先使用此前易出问题的同一场景，M2、T58、PRE0，不同时换线或调其他参数。连续观察约 5 分钟，重复手、人脸和复杂背景进出画面，再看 M7 和 M0。T/PRE 通过原按钮调到相同值；这版没有新增按键操作。

反馈重点是 M2 是否仍有“显示器无信号/整屏连文字消失”，而不是正常边缘数量随场景变化；同时记录大致持续时间。若 M2 稳定，说明此候选在该次实板条件下有效，但仍不能独立证明原 IP 算法错误，因为替换也改变了消隐码流、资源和布局。若 M2 仍失锁而 M7 稳定，则该替换不足以解决问题，需要继续测量码型相关的物理输出/电源/时钟余量；继续降低阈值没有针对性。

如果新版本在所有页都无信号，回退原 E5 固件，可能涉及新传输的兼容性或板级时序；保留本次现象，不要改引脚/PLL 试碰运气。

## 验证与边界

独立 Python 模型由实际 10 位符号的 1/0 数更新有符号直流平衡，并逆解码校验原 8 位输入。穷尽可达平衡状态与所有 256 种字节的组合，另外逐拍检查黑白长段、棋盘交替、彩色伪随机、三通道独立、全部四种控制符号、2200 拍行周期及中途复位。它验证新编码器的功能，没有仿真原加密 IP 或模拟电气链路。

另运行实际处理核心的 M2/M7 对照、八页/原七页控制、PRE 长按、E6D HUD、欠载恢复及工程接口/结构检查。原 E5 发布文件逐项核对 SHA256，保留原版本供回退。实际编译、时序和资源数字见 `reports/V10_E6_VALIDATION.md` 和 `e6_release_manifest.json`；旧 E3～E5 报告为历史材料。
