# V10-E3 弱轮廓支持实验

基于 `D:\FPGAdemo\v10-e2\ti60f225_oob` 的 E2L。现有 E2 原目录、两版固件及发布记录保留。E3 是待上板确认的实验，不能将编译、仿真通过当成真实画质改善。

## 本轮反馈与目标

用户实板反馈：E2L 较 E2N 噪点少；T=68 多数边缘存在、噪点少，但少量边缘缺失；T=47 弱边缘较全，背景有随机跳点；T=40 跳点更多。补光后部分轮廓恢复，M5 梯度幅值图仍可看到一些最终二值图中缺失的轮廓。当前资料是拍屏照片与描述，没有直接摄像头帧和人工真值，不能据此量化真实召回率或认定对焦故障。

本轮只增加弱轮廓支持路径及预处理状态显示。没有全局降低阈值、减少原三种子门槛，未改预处理顺序、相机曝光、颜色、DDR、MIPI、HDMI、PLL、复位、SDC，也未实现整帧滤波或完整 Canny。

## 两版固件

| 标识 | 内容 | 用途 |
|---|---|---|
| E3B | 原 E2L 算法，加 PRE 状态显示 | 同显示方式的基准 |
| E3W | E3B 加可关闭的弱轮廓补充路径 | 实验版 |

两版上电 T=50、PRE=0（旁路），低阈值仍为 ceil(T/2)。原颜色 PH2 / BGGR、十六进制增益 R240/G180/B240 不变。核心延迟仍为 `5*HTOTAL+60`，1080p 配置为 11060 时钟；不增加行 RAM 或整帧缓存。最终固件是否可交付，以 `reports/e3_release_manifest.json` 及验证报告为准，不要烧录历史 E2 文件冒充 E3。

## 新增规则

原 E2 方向约束局部图、桥接和至少三个强种子的规则完整保留。E3W 取原 E2 输出与以下补充路径的并集：中心所在的五个连续点必须全部为原始低阈值 NMS 候选、梯度法线分档完全一致，并且至少一个点为原始高阈值 NMS 种子。

只检查穿过中心的水平、垂直、两条对角切向线，长度固定为 5。原始点不经过额外桥接才能进入这条路径；缺点、无强种子、错误法线或短小点簇不能凭这条路径通过。补充判定与旧图传播流水等长，控制和像素对齐保持。

顶层 `E3_WEAK_CHAIN_ENABLE=1` 选择 E3W，设 0 为 E3B。`img_pipeline` 和 `img_edge_link` 的 `WEAK_CHAIN_ENABLE` 默认 0，以便原有仿真按原规则回归。高低阈值比例、MIN_SEEDS=3、NMS 平台策略均保持，避免一次同时改变多个质量因素。

这是保守的局部补充：主要帮助强支持不足的短直弱段；弯曲、数字阶梯线、较长且无邻近强种子的弱轮廓仍可能缺失，也可能少量增加噪声响应。它没有提供新的时间去噪能力，不能承诺随机跳点消失。

## 按键与可见反馈

普通页右侧新增 `PRE:0/1/2/3`，M6 也显示当前 PRE。`PRE:0` 为旁路，1 中值，2 高斯，3 锐化。`S:1` 仍表示阈值步进，`PH:2` 仍表示 Bayer 相位，均不是预处理编号。

短按原模式键循环 M0–M6。在非 M6 页，按住该键约 2 秒再松开：PRE 应每次增加一次，循环 0→1→2→3→0，M 编号保持原值。一次持续长按不会反复切换，新的预处理在输入帧边界生效。M6 长按仍切颜色调节项，不切预处理；不要在那里误调颜色。

若非 M6 页 PRE 仍不改变，说明实板按键识别问题尚未解决，不能仅凭画面变化认定已经开启滤波。新增的是可见状态，并非未经实板证实的按键故障修复。

## 首次上板对比

固定照明、距离、杯子和预处理，先 E3B 后 E3W，均设置 T=68、PRE=0，以用户已确认噪点较少的工作点比较。主要看 M2 的杯身外沿、杯盖下沿、梅花图案、细字和背景跳点；M3 仅作方便观察的缩略对比，M4 核对贴合，M5 仍是未按最终规则筛选的梯度幅值。

只有两版同条件比较后，才考虑 PRE=1/2 的单独实验。避免同时降低 T、换滤波和更换固件，以免无法判断变化来自何处。原 E2 的稳定性、冻结、模式/阈值边界及至少 30 分钟运行项目仍需实板覆盖。

## 复现

本机检查入口 `scripts/run_e3_checks.ps1`：`-Suite regression/local/images/structure`。额外按键/HUD 检查为 `scripts/verify_e3_controls.py`，需相同环境。`scripts/build_e3.ps1 -Variant W/B` 执行真实 Efinity compile，B 构建由 `prepare_e3_baseline.py` 建立，不覆盖既有缓存。

Efinity 安装在 `D:\efinity\2026.1`。接口工具通过 EFXPT_HOME 指向工作区内未经源码修改的副本 `D:\FPGAdemo\tools\efinity_pt`，解决受限安装目录访问问题。Icarus 使用 `tools/iverilog/app` 中的 v12 工具，`icarus_direct.py` 分别运行原版 ivlpp 和 ivl，再由 vvp 仿真，避免 Windows CLI 驱动异常；每一阶段检查退出码，编译错误不允许被忽略。该入口仍是实际 RTL 仿真，不是 Python 模型替代硬件。

`reports` 中带 e1/e2 或旧日期的报告为历史记录。E3 本轮证据使用 e3 前缀文件；最终汇总及 SHA256 由 `finalize_e3.py` 在全部结果存在后生成。
