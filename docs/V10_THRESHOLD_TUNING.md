# V10 手动阈值、暗部边缘与黑屏说明

## 哪个是最终结果

算法链为 RGB→灰度→可选前处理→3×3 Sobel→`|Gx|+|Gy|`→阈值比较→显示合成。当前没有实现 Canny 的非极大值抑制、双阈值和连接追踪，不应把结果称为 Canny。

| 屏幕 M 值 | 图像意义 | 调阈值的作用 |
|---|---|---|
| 0 | 彩色原图 | 不改变原图，只保存阈值设置 |
| 1 | 灰度原图 | 不改变灰度，只保存阈值设置 |
| 2 | **最终二值边缘结果**：满足阈值的像素白，其余黑 | 直接改变边缘数量 |
| 3 | 左原图，右最终二值边缘；两侧为同一完整水平视野 | 改变右侧 |
| 4 | 原图叠加红色最终边缘 | 改变红色叠加 |
| 5 | 梯度幅值灰度预览 | 不改变梯度；这还不是最终二值结果 |
| 6 | 彩色白平衡与诊断 | 此页 KEY1/2 调 RGB 增益，阈值不变 |

用户称“第三个模式”时，可能指模式2，也可能指按键计数；照片没有可读模式号，不能单凭照片确定。V10 参数条直接显示 M，避免混淆。上电模式为3，短按循环 `3→4→5→6→0→1→2→3`。

## 按键

- 普通页 KEY1：阈值+1；KEY2：阈值-1。降低阈值能保留更多弱边缘，也会保留更多噪声。
- 取值范围 **4～128**，默认 **24**。单次短按调整1；长按约0.5秒后，每0.1秒调整1。
- 达到128后继续加保持128，参数条变黄并显示 MAX；达到4后继续减保持4并显示 MIN。不会回绕至负数、零或大数。
- host 配置写入也限制到4～128。pending 设置只在下一帧开始提交，避免半帧改变比较标准。
- KEY3短按换显示，长按换前处理（模式6长按选R/G/B）；KEY1+KEY2同按冻结；KEY0整板复位。
- 模式6保留原白平衡功能，增益只在按下时调整，不启用阈值长按连调。

`V10 M:3 T:024 MAX:128 S:1` 中，T和MAX均为**十进制**。模式6的T也为十进制，RGB/GAIN/N等原诊断项保留十六进制。模式0～5常驻小参数条，视频主体不被覆盖。

## 暗部为什么弱，如何调

Sobel检测亮度变化。暗区域内的灰度差小时，算出的梯度也较小，统一阈值更容易将其过滤掉。降低阈值可以改善这一情况，但不会创造源图像中不存在的细节。

软件测试使用灰度16和24构成暗部阶跃，差值8，对应竖直边界的Sobel幅值32。旧默认阈值40将其全部过滤；阈值24检出12个有效边缘像素；阈值4也检出12个。亮部差值64在阈值128仍检出12个；完全均匀的暗图即使阈值4也输出零边缘。该测试验证比较行为，不是实拍质量测量。

上板先在M:3观察左右对比，用KEY2把24逐步减到20、16、12；出现较多散点时再适度提高。可长按KEY3切换中值等前处理，但滤波也可能去掉细微纹理。V10没有增加自动曝光、局部自适应阈值或亮度补偿，便于先用手动参数定位问题。

## 上限与黑屏的区别

V9已对11位数值2047做饱和，但这个数远超过多数实时画面的有效梯度，容易出现“整幅边缘都被滤掉”。V10把板级手动上限收至128，避免无意义地继续增大；12位中间加法先比较再截位，防止加法溢出，减法也先做下限判断。

**设置128上限不能保证图像永不全黑**：场景没有足够对比时，任何正阈值都可能输出全黑。此时参数条仍应可见，HDMI仍保持同步。真正显示器报“无信号”、参数条消失或重新识别HDMI，需要另查视频同步、复位/PLL和物理链路，不能用阈值上限掩盖。V9的连续raster及帧恢复结构在本版保留。

## 实板验收

1. 烧入 `programming/ti60f225_oob_V10.bit`，确认左上角 V10、MAX:128、S:1；按M值判断所处页面。
2. 在M:3用KEY2从24下降，暗部细节应逐渐增加；在M:2看相同参数的最终二值结果。
3. 长按KEY1直至128，再额外按/长按，T必须保持128，MAX变黄。长按KEY2降至4后继续操作，T必须保持4。
4. 在M:0、1、5测试同样的上下限操作：图像不应随阈值变化，参数条应更新且同步不应中断。
5. 切到M:6查看 U/D/R/L/O 锁存标志。若发生真正无信号，记录发生前的M/T值、标志及是否自动恢复，继续定位。

本版完整仿真、综合和STA结果见 `reports/V10_VALIDATION.md`。源端相机帧周期未修改；HDMI目标仍为1080p60，实际相机新帧率仍需板卡测量。
