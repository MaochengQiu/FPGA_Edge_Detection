# E7Q：去噪强度对照候选

本版针对用户反馈的平坦背景碎点、毛边和弱轮廓取舍。用户反馈 E6 的黑屏频率已明显下降，但场景或模式变化时仍可能偶发，因此稳定性尚未完全确认。本次沿用 E6 的纯视频编码器、PLL、引脚、串化和约束；资源和布局随重编译变化，实板仍需观察稳定性。

## 当前入口与操作

烧录 `programming/ti60f225_oob_V10_E7_Quality.bit`，屏幕应显示 E7Q。上电仍为 M3 分屏，默认阈值 T50，PRE2。M0～M7 保留，M7 是同一边缘位的不同显示色值，并非另一套边缘算法。

普通页原模式键短按换 M，长按约1～2秒再松开使 PRE 增加一次。一次持续按住不会连续切 PRE。M6 长按仍用于调色项选择，应在 M2/M3/M7 等普通页切 PRE。

| PRE | 本版含义 | 与 E6 的关系 |
|---|---|---|
| 0 | 不滤波 | 保留，供观察原始细节和噪点 |
| 1 | 3×3 中值 | 保留运算；共同窗口使有效边界略收窄 |
| 2 | 5×5 高斯 | 新增更强平滑，默认起点 |
| 3 | 3×3 高斯 | 原 E6 的 PRE2；替换原 PRE3 锐化 |

先固定相机位置、光线、物体和 T50，在 PRE2 与 PRE3 之间比较。主要看平坦背景的跳点、杯身外沿、弯曲图案和细字；多切 PRE 不需要换固件。PRE0 和 PRE1 作为辅助参照。

如果 PRE2 背景明显更干净但有弱边缘丢失，再保持 PRE2，从 T50 降到 T46 比较。若背景仍碎，可提高到 T54。这里的 46/50/54 是小范围调节起点，不是从拍屏测得的最优值，也不是与其他库阈值的对应关系。每次只改变一项，避免同时调 T 和 PRE。

更强平滑也会减弱细线和弱对比轮廓，不能承诺比 PRE3 保留所有边缘。优先选出实际场景更合适的 PRE，再微调 T。没有在本轮增加盲目膨胀、闭运算或提高强种子数量。

## 具体改动

灰度预处理使用一个共同的中心 5×5 窗口。PRE2 是精确整数核 `[1,4,6,4,1]` 的外积，除以256，仅末次加128后取整；没有两次3×3滤波的中途量化。PRE1/PRE3 从该窗口的中心3×3取样。

所有 PRE 和显示页统一增加 `HTOTAL+1` 个像素时钟延迟；核心总延迟为 `6*HTOTAL+61`，1080p/HTOTAL2200 时为13261拍，比 E6 多2201拍，约14.82微秒。RGB 对齐、DE/HS/VS、NMS 和连接数据随同一像素中心推进。滤波模式的梯度有效区域排除外侧3像素，PRE0仍排除1像素；连接和NMS还各有各自的边界限制。这避免无效窗口或上帧 RAM 数据形成伪边缘。

NMS 非严格平台规则、三强种子门槛、局部5×5方向连接、低阈值 ceil(T/2) 和桥接保持。严格 NMS 只作为同输入离线对照，没有启用到上板版本。线条更少并不等于真实轮廓更完整，当前缺少相机原始帧和人工标注。

相机、DDR、Bayer 相位和色彩增益、gamma、E6 DVI 编码、输出取反、PLL、驱动设置、串化、引脚和 SDC 均保持。M2 仍纯黑白，M7 保留原近黑/近白对照色；调试期间暂不删除 M7。

## 检查与证据

`scripts/verify_e7.py` 验证高斯算术、跨帧 PRE 变化的 RGB 延迟、M2/M7 一致性、控制默认值和八页循环、原控制/PRE长按、E7Q HUD、欠载和恢复。`verify_e7_images.py` 在同输入下运行实际 RTL，并对每个像素及每个同步拍核对独立整数模型，输出 `reports/e7_quality/comparison.png`。

图像包含缩放后的既有杯纹/文字/公开人脸图片，及已知平坦噪声、已知竖直阶跃的合成输入。只有合成平坦区可计算误响应像素，已知竖边可计算逐行覆盖；不能把这些数字称为真实摄像头召回率、参考视频复现率或实板效果。用户当前拍屏与理想参考图不是同输入，未直接从两张图推算参数。

实际编译、资源、时序、图像数字见 `reports/V10_E7_VALIDATION.md` 及 `e7_release_manifest.json`。原 E6 发布文件按 SHA256 核验保留。目录中 E3～E6 报告和入口均为继承历史，不能当成本轮新结果。
