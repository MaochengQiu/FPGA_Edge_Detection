# V3 运动优先 / 帧更新诊断（2026-10-21）

## 本次的判断：不要混淆三类现象

1. **拍摄运动拖影**：曝光时间过长会把运动边缘平均掉；即使把 Sobel 阈值降到 0 也找不回丢失的物理细节。
2. **源帧率低/帧缓存未完成**：摄像头输出、AXI 成功写入、显示帧周期是三个不同指标。只有看计数才能知道在哪一级掉帧。
3. **显示的帧缓冲延时**：当前结构先整帧写 DDR，再等 HDMI 帧边界选择最新完整帧，理论上会有至少帧级滞后。V3 **没有改成直接视频旁路**，不能承诺严格低于某个毫秒值。

## V3 代码变更

- `rtl/cam_i2c_ctrl/i2c/i2c_master_reg_rom.v`：仅改变 SC431HAI 手动线性曝光 `0x3e00/01/02`，旧值 `01/BB/F0` → `00/50/00`。手册的编码定义为 `{3e00[3:0],3e01,3e02[7:4]}`，即从 `0x1BBF`（7103 半行）改为 `0x0500`（1280 半行/640 行），相差约 5.55 倍。手册给的默认 VTS=1500 行，**若硬件确实使用该默认 VTS**，曝光最大值 `2*1500−11=2989` 半行，旧初始化超过范围，新值在范围内。**不要把这个推导等同于实际测得的帧率**；板上可能配置了其它 VTS/时钟，必须读取寄存器或观察 HUD 复核。
- 想退回旧曝光，只需在 Efinity 项目编译宏定义中设置 `EDGE_ORIGINAL_LONG_EXPOSURE`；或将这 3 个值恢复，不涉及 PIN/IP/PLLs。
- `rtl/edge/control/img_control.sv`：默认预处理调整为 **mode 0（直通）**、阈值仍 40；降低运动场景高光经锐化饱和后边界被压平的风险。mode 3 强化仍可长按 KEY3 切换。**没有声称静态弱纹理会在本版自动变好**。
- `rtl/edge/compose/edge_video_health.sv`：新增显示帧率 HUD。跨时钟使用 1-bit 事件 toggle + 两级同步器；摄像头 VS 下降沿产生 C 计数，DDR 一帧成功写入产生 d 计数。以**60 个输出 VS 周期**为窗口更新读数；仅在输出刷新确实 60Hz 时，读数才约等于真实 FPS。
- `rtl/ti60f225_oob_top.v`：加入事件采集/实例连接到 gamma 和旁路共同的画面输出。**未改变**摄像头、DDR3、HDMI、任何外围引脚、时钟、分辨率、核心 IP 参数或物理接口。
- `ti60f225_oob.xml`：仅登记一个新增 RTL 源文件，源文件数 68→69；器件与 Efinity 实现设置、GPIO/peri、SDC 原样。

## 屏幕 HUD 阅读

当没有覆盖全屏文字时，最上方两侧各有一个细窄状态条，不影响下面图像。左侧 `Cxx` 表示摄像头平均每 60 个 HDMI 帧周期的到达帧数；右侧 `dxx` 表示 DDR 成功写入的完整帧数。同一条内小色块依次表示：

- 红色：存在拒绝发布帧（`rejected_frames` 非零新增事件）。
- 橙色：出现读取请求太晚（`late_requests` 新增）。
- 品红：摄像头侧 FIFO 溢出（`capture_overflows` 非零）。
- 黄色：当前被按键组合键切换到 freeze（冻结）模式。

发生过的故障指示在本次上电期间常亮，复位后清空。数字约每 60 个输出帧更新一次；**若显示器实际不是 60Hz，数字不是绝对每秒帧率**。本 HUD 不测得摄像头曝光实际行时间和 HDMI 输入到输出的精确端到端时延。

| 观察 | 初步方向 |
|---|---|
| C≈30，d≈30，仍感到明显延迟 | 完整帧 DDR 和 HDMI 选帧造成的滞后/显示路径，需进一步用闪光时标实测 |
| C 很低，d 也很低 | 首先看摄像头曝光、VTS、CSI 完整帧和时钟 |
| C 高、d 低 | CSI 帧进入但没有成功写 DDR：检查 FIFO、拒绝、AXI、内存吞吐 |
| C、d 正常但运动时轮廓变淡 | 运动模糊、镜头对焦、Sobel 阈值/增强，不能单凭FPS推定 |

**注意**：C 只数相机 VS，不检查这一帧是否传输完整；d 才是完整 AXI 写入成功信号；请优先结合红/橙/品红告警判断。

## 分阶段上板测试（先动态，后纹理）

1. Efinity 重新综合、P&R、时序验证和下载全新 bitstream（压缩包里旧 outflow 不是 V3 编译结果）。
2. 上电等待 HUD 数字出现，把显示器最上方 C、d 读数和右侧故障点拍清楚。不要用之前的 bitstream。
3. 固定光照，快速横移黑白棋盘格，录 5~10 秒 60fps 慢放，重点看运动时是否保持连贯轮廓。再静止对着纸杯观察；必要时长按 KEY3 切回 mode 3 锐化。
4. 如果新曝光画面明显偏暗，先增补照明；如确有必要可将 `0x3e01` 从 `0x50` 适当提高到 `0x60/0x70` 再复测，但应先确认传感器读回的 VTS 与曝光上限。**不要恢复明显超出 VTS 限制的长曝光**。
5. 若 C 和 d 均正常却仍出现约 0.5 秒延迟，提供有计时标尺的屏摄视频/示波器帧同步；此时必须对 DDR 读请求与 HDMI 输出做端到端时戳验证，不能靠猜测继续改 Sobel。
