# V10-E1 边缘优化实验版

## 基准与隔离

E1 放在 `version/e1/ti60f225_oob`，由现有色彩完成版直接复制修改。实际冻结基准是 C2 系列最后交付的 C2.1，它仅将用户已确认的 PH2 BGGR、R/G/B 增益 0x240/0x180/0x240 固化为默认值。没有回到早期 C2 的中性增益和试验相位，也没有重新调整色彩。

稳定项目 `version/v10/ti60f225_oob` 及其 C2、C2.1 固件、包和发布清单保持不动。`scripts/check_e1_scope.py` 会检查稳定版所有发布文件 SHA256，并将 E1 编译源与冻结基准比较。

## Sobel 精度检查结论

原 Sobel 是四级流水：加权正负部分和、带符号差值、绝对值、L1 幅值。每个正负部分和范围 0～1020，使用 10 位；Gx/Gy 使用有符号 11 位，范围足够容纳 -1020～1020；绝对值和幅值使用无符号 11 位，不存在先截成 8 位再做阈值的问题。

Sobel 二值输入顶点穷举及随机窗口已与独立整数参考比较。8 位输入时，Gx/Gy 各自绝对值最大 1020，可同时达到的 L1 幅值最大为 1530；11 位可容纳。原 `mag>=threshold` 比较和边界有效性继续保留。M5 的 `min(mag,255)` 只是预览映射，不参与阈值或 NMS 比较。

因此本次没有修改正确的 Sobel 计算或阈值范围，也没有整体替换算子。M5 比 M2 丰富的主要原因是 M5 显示强弱梯度，而 M2 只保留超过单阈值的响应；宽梯度平台也会直接显示为粗线。低于阈值的真实弱轮廓不会因为增加 NMS 自动恢复。

## NMS 实现

在原 `edge_q`/`mag_q` 后新增一个三乘三梯度邻域。邻域 RAM 存储完整 11 位幅值、2 位方向和 1 位有效标记。利用现有 Gx/Gy 计算四档梯度法线方向：0 水平，1 左上/右下，2 垂直，3 右上/左下；坐标 y 向下，不能混淆法线与轮廓切向。

方向量化使用 424/1024 近似 tan(22.5°)，不使用 atan 或除法。仿真包含正负象限、轴向、极值及分界附近。与浮点角度分类只允许在量化分界附近发生差异，实测范围在验证 JSON 中。幅值始终保持 11 位，避免强边缘显示饱和后变成假相等平台。

比较拆成邻居选择和极大值判定两个寄存级。默认规则为：中心不为零、中心不小于沿法线两邻居，并且严格大于其中至少一个；同时中心和这两个邻居都必须有效。完全平坦的三个相等响应不保留；无效行帧边界不使用未初始化 RAM 数据。

最初的严格单侧规则会让合成数字圆弧和 PCB 斜线产生更多断点。因此默认选择保留平台峰值的策略，允许相等峰值形成少量双像素线段，以换取连续性。严格规则仍可通过 `E1_NMS_STRICT_TIES=1` 使用：中心 >= 前邻居且 > 后邻居。两种规则都有独立 RTL 向量验证。NMS 并不保证所有真实轮廓恰好一像素宽，也不保证消除孤立噪声峰值。

## A/B 使用

- `programming/ti60f225_oob_V10_E1_NMS.bit`：实验默认，显示 **E1N**，开启 NMS，采用默认平台策略。
- `programming/ti60f225_oob_V10_E1_Sobel.bit`：对照，显示 **E1S**，关闭 NMS，恢复原 C2 Sobel 二值判定。它与 E1N 有相同的新增延迟，便于比较。
- 顶层参数 `E1_NMS_ENABLE` 控制开关，默认 1；`E1_NMS_STRICT_TIES` 控制平台策略，默认 0。改变参数后需要重新编译，不是运行中按键开关。
- 原 C2/C2.1 `.bit` 仍可直接回退。E1 不覆盖稳定版，也不会自动写入开发板。

NMS 只允许抑制原来已过阈值的同一个像素：`final_edge = 原Sobel判定 && NMS保留`。关闭时直接使用原判定。因此同一输入、同一预处理、同一阈值下，E1N 的边缘集合是 E1S 的子集，不能宣称它靠 NMS 增加了低于阈值的召回。也没有暗中降低阈值。

## 延迟与模式对齐

原核心延迟为 `2*HTOTAL+22` 个像素时钟。E1 统一增加 `HTOTAL+5`，变为 `3*HTOTAL+27`；1080p、HTOTAL=2200、148.5 MHz 下新增约 **14.85 微秒**，是 1 行加 5 个时钟，不是增加一帧。

原 RGB、灰度、完整幅值、原二值判定和显示配置全部延迟相同长度，DE/HS/VS 独立同延迟，处理吞吐仍为每时钟一个像素，没有 backpressure 或新的整帧缓存。原摄像头、DDR、MIPI、PLL、复位连接和 HDMI 编码/物理输出不改。

- M2 用所选二值边缘全屏显示。
- M3 的左右视图继续来自同一完整图像，保留已有横向 2:1 抽样和上一源行成对显示行为；左右共同延迟，不能把原有行抽样当成新增失配。
- M4 红轮廓与同一中心像素的 RGB 对齐。
- M5 继续显示原始幅值，未换成细化幅值；其像素值在 A/B 中一致，只增加同样的短延迟。
- M0/M1/M6 内容、PH2、增益、阈值 4～128/默认24/步进1、按键、冻结及诊断功能保留。HUD 只更改版本/路径标识 E1N/E1S。

## 固定输入的可重复验证

`scripts/verify_e1.py` 将固定图送入真实 RTL，而不是只绘制 Python 算法结果。同一批输入分别运行 NMS 关/开，两边均保持 T=24、预处理旁路。全部输出逐像素与独立参考比较；接着由 RTL 结果生成 `reports/e1_ab/comparison.png` 及单图。

输入含棋盘格、纸杯轮廓与花纹、印刷文字、PCB 线与过孔、人脸和三帧运动序列。棋盘格、杯纹、文字、PCB、运动序列是明确标注的合成测试图；人脸来自 scikit-image 官方公开照片，手工固定裁剪，不涉及人脸识别。旧的人脸反馈临时文件已不存在，因此没有将其冒充本轮输入。所有实际输入 PNG、来源说明和 SHA256 都随包保存。

这些图用于重复验证与观察，不能替代真实纸杯、PCB、肤色和移动摄像头的实板测试。没有人工标注真值，所以不报告 Precision/Recall/F1。记录的白像素数、实心 2×2 块、8 连通分量、端点和孤立点只是描述性指标，不是通用质量得分；边缘数减少本身不证明更好。

额外的合成模糊阶跃有已知的原始几何边界，可报告该个测试上的横向定位误差和响应宽度，不能把它推广为实拍定位精度。具体实际数值在 `reports/V10_E1_VALIDATION.md` 和 `e1_algorithm_verification.json` 中。

## 双阈值与连接的评估边界

另有 **CPU 离线**高/低阈值与 8 连通泛洪实验：T_high=24，T_low=12，检查长串弱响应能连接至强边缘、而不相连的弱岛被拒绝。只检查强边缘相邻一圈会漏掉长弱链，单次前向扫描也不能正确处理反向连接。

该实验没有合入 RTL 默认输出。完整连接追踪通常需要可回访的状态或迭代，本轮没有改 DDR/帧结构，也没有将有限邻域近似命名为完整滞后追踪。E1 是 **Sobel + NMS** 实验，不是完整 Canny。轮廓断裂、低于单阈值的细节和真实噪声控制仍是后续独立工作的重点。

## 实板验收

保持机位、照明、预处理和阈值不变，分别烧录 E1S、E1N，优先在 T=24 比较；确认 E1N/E1S 标记，PH2 和 240/180/240 不变。先看 M2 线宽、圆弧/斜线连接和噪声，再看 M3 左右对应及 M4 叠加位置，确认 M5 内容正常。

使用真实棋盘格、纸杯花纹、文字、PCB、人脸；运动物体和冻结/解冻、反复切模式/调阈值都要覆盖，观察 HDMI 不丢信号、U/D/R/L/O 无新增异常。两种 E1 固件都尚未上板，不能用本地时序/仿真替代此确认。若 NMS 丢失了有用线段，先保留 E1S 作为对照并记录具体场景，不用降低阈值掩盖问题。

参考：[OpenCV 的 Canny 步骤说明](https://docs.opencv.org/3.3.0/da/d22/tutorial_py_canny.html)、[scikit-image 对 8 连通滞后阈值的定义](https://scikit-image.org/docs/stable/api/skimage.filters.html#skimage.filters.apply_hysteresis_threshold)、[公开人像测试图来源与许可](https://scikit-image.org/docs/stable/api/skimage.data.html#skimage.data.astronaut)。这些资料用于界定 NMS 与连接步骤，不表示 E1 实现了完整 Canny。
